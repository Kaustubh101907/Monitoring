### 🛠️ What is this Service?

This is the **LGTM Stack** (Loki, Grafana, Tempo, Monitoring).
It is a collection of open-source tools that work together to create a complete monitoring system.

* **Prometheus:** The Brain (Remembers the numbers).
* **Grafana:** The Face (Shows the pretty charts).
* **Loki:** The Logbook (Reads the text files).
* **Agents (Node Exporter/Alloy):** The Spies (Gather the data).

---

### 📝 The Breakdown

Here is every tool and concept mentioned in your transcript, simplified:

**1. Prometheus (The Metrics Database)**

* **What it is:** An open-source toolkit that stores metrics. Think of it as the database for your monitoring.
* **How it works (The Pull Model):** Prometheus uses a method called **Scraping**.
* *Analogy:* Prometheus is like a teacher walking around the class asking each student (server), "What is your temperature?" It **pulls** the data.


* **Time Series Data:** It stores data based on time (e.g., CPU was 50% at 10:00 AM, 60% at 10:01 AM).
* **PromQL:** This is the specific coding language used to ask Prometheus questions.
* **Dashboard:** Prometheus has a UI, but it is basic and ugly. We rarely use it for visualization; we use it just to check if the targets are alive (UP/DOWN).

**2. Grafana (The Visualization King)**

* **What it is:** The "Frontend" of your monitoring stack. It connects to Prometheus and Loki to make the data look beautiful.
* **Features:**
* Creates fancy **Dashboards** (Graphs, Pie Charts, Gauges).
* Highly customizable (you can even use JSON code to tweak it).
* Sends **Alerts** (Notifies you if something breaks).


* **Data Sources:** It pulls metrics from Prometheus and logs from Loki.

**3. Loki (The Log Aggregator)**

* **What it is:** It is "Prometheus for Logs."
* **Function:** It collects text logs (error messages, system events) from all your servers and stores them efficiently using **Labels**.
* **Integration:** You view these logs inside Grafana.

**4. The Agents (The Spies)**
You need small software installed on your servers to expose the data so Prometheus can scrape it.

* **Node Exporter:**
* This is a lightweight agent for Linux/System metrics.
* It exposes CPU, Memory, Disk, and Network data.
* *Workflow:* Node Exporter runs on the server -> Exposes metrics on a port -> Prometheus scrapes it.


* **Promtail (Outdated):**
* Used to read log files and **push** them to Loki.
* *Note:* It is being phased out.


* **Alloy (The New Hero):**
* This is the new **"All-in-One" Unified Agent** from Grafana Labs.
* It can collect **Metrics** (replacing Node Exporter), **Logs** (replacing Promtail), and **Traces**.
* We will use Alloy in this course because it is the modern standard.



**5. Alert Manager**

* This is the delivery boy. Prometheus detects a problem (e.g., "High CPU"), sends it to Alert Manager, and Alert Manager sends the email, Slack message, or PagerDuty notification to you.

**6. The Architecture & Ports (Important for Firewalls!)** 🔌
You need to know which port numbers these services use to talk to each other.

* **Grafana:** Port **3000** (This is where you log in to see charts).
* **Prometheus:** Port **9090** (The transcript says 1990, but the standard is 9090. Grafana talks to this port).
* **Loki:** Port **3100** (Alloy pushes logs here).
* **Node Exporter:** Port **9100** (Runs on the application server. Prometheus visits this port to scrape data).
* **App Metrics:** Port **5000** (Example port where your custom app might expose its own data).

---

### 🚀 Summary

* **Prometheus** *pulls* (scrapes) **metrics** from your servers.
* **Loki** receives **logs** *pushed* by agents.
* **Grafana** sits on top, connects to Prometheus and Loki, and shows you the **Graphs** on Port 3000.
* **Node Exporter** provides system data (CPU/RAM).
* **Alloy** is the new all-in-one agent that collects everything (Metrics + Logs).
* **Alert Manager** sends the notifications to Slack/Email.
